## 分析目标

1. **差异识别**：识别工作项的新增、变更、移除
2. **风险识别**：按四象限标准识别风险（阻塞/延期/资源/依赖）
3. **趋势判断**：对比上次汇报，判断风险是加重还是减轻
4. **给出建议**：针对每个风险给出可操作的缓解建议

---

## 风险识别标准

| 风险类型 | 定义 | 关键信号 |
|---------|------|---------|
| **阻塞** | 任务完全停滞，无法推进 | "被阻塞"、"卡住了"、"无法推进"、"等审批"、"搁置"、"暂停" |
| **延期** | 进度显著落后于计划 | "延期"、"延迟"、"晚于"、"来不及"、"赶不上"、"还没开始"、"进度 XX%" |

## 分析原则

1. **差异要具体**：不要写"进度有变化"，要写"支付模块从设计阶段进入开发阶段"
2. **风险要真实**：只提取真正的风险信号，不要过度解读正常的工作描述
3. **建议要可操作**：给出具体行动建议，而非泛泛的"需要关注"
4. **趋势要对比**：如果上次汇报已存在同类风险，判断加重/减轻/持平；如果是新出现的风险，标注"新增"
5. **依赖要明确**：明确指出依赖的具体对象（人/团队/系统）
6. **没有风险时**：risks 输出空数组 `[]`
7. **首次汇报**：如果这是该人的首次汇报（无上次汇报对比），is_first_report 设为 true，risks 和 diffs 可适当简化

## 整体评估指引（由 Agent 综合分析所有人员后生成）

在完成所有人的逐人分析后，Agent 需综合判断，生成以下整体结论：

### 整体风险评分（1-5）

| 分数 | 含义 |
|------|------|
| 1 | 整体无异常，正常推进 |
| 2 | 低风险，有个别小问题但可控 |
| 3 | 中等风险，存在需关注的延期/资源/依赖问题 |
| 4 | 高风险，有阻塞或重大延期，需管理介入 |
| 5 | 严重风险，多个阻塞叠加，项目可能失败 |

### 整体评估摘要

一段话描述整体态势，包含：
- 总体人数和风险概况
- 最突出的风险信号（具体人和事）
- 亮点/进展（如有）

### 重点关注事项

使用 `问题描述——缓解建议` 格式：
- 每个事项一句话，用 `——` 分割问题与建议
- 示例：`"新信贷信创服务器资源短缺导致项目阻塞——建议管理部紧急协调资源"`
- 示例：`"刘程离职导致关键岗位空缺，面试未通过——建议加快招聘或多渠道协调人力"`
- 列出 3-8 个最紧急事项，按严重程度排序
